# 动态镜头：分档、动作写法、审片、模型选择

来源：一个 4 分钟歌曲 MV 项目。60 个镜头里 59 个交给了 Wan，花了 19.4 小时 GPU，用户看成片觉得很多画面不合逻辑。下面的规则都是从那次的数据和之后的对比测试里来的。

## 动态分档（D2 写进分镜表，D5 定稿）
镜头字段 `motion_tier`（可选；不写 = 旧行为，交给 Wan）：

| 档 | 做法 | 逻辑风险 | GPU |
|---|---|---|---|
| `camera` | Ken Burns 推拉摇（`move`: in / out / left / right / up / still） | 无 | 0 |
| `overlay` | Ken Burns + 代码叠加层（`remotion/src/Ambient.tsx`）：`dust / flies / fireflies / embers / snow / rain / steam / flicker`。写法：`"overlay": {"type": "flies", "region": [0.3, 0.3, 0.7, 0.7]}`，可以写成列表叠多层。Remotion Studio 里的 `AmbientDemo` 合成可以预览全部类型 | 无 | 0 |
| `ai_env` | Wan 只动环境或物体：水、烟、布、光、远处车流 | 低 | 1 条 |
| `ai_action` | Wan 动人，一条只做一个动作 | 高 | 1 条 + 严格审片 |

- 用户说“太静了 / 要动起来”时，按 camera → overlay → ai_env 往上加，`ai_action` 只给剧情非它不可的镜头。苍蝇、灰尘、蒸汽、烛光这类效果就该用 overlay，不要让 Wan 画。
- `camera` / `overlay` 镜头和裁切镜头（`reuse_of`）不进 Wan 队列。overlay 也可以叠在 Wan 片段上。

## 动作提示词怎么写（`lint.py` 的 `[motion]` 检查会提醒，都是 WARN）
那个 MV 的动作提示词，中位数同时写了 4.5 件事，还有“害羞地笑 → 摸后脑 → 低头 → 再抬头笑”这种连续表演。规则：
- 一个主动作 + 镜头运动；环境小动作（雾、闪烁、水纹）加起来不超过 3 件。
- 不写先后顺序（then / after / until）。一条片段只够一个节拍，多个节拍就拆成多个镜头，或用 `continue_from` 接续。
- 不让东西进画（appears / enters / walks in / someone）。要出现的东西画进关键帧，或者切到下一个镜头。
- 动作里提到的东西，关键帧提示词里必须有，否则 Wan 会现编（实际出现过：冒出肥皂瓶和黑影，灯笼飘走）。
- 人物表演（大笑、说话、手势、走路、转身）只放在 `human_motion` / `ai_action` 镜头；微笑、点头、呼吸、抿一口可以留在 `human_static`。
- 人物卡加 `"hold_still": true`：这个人物所在的镜头只动镜头和环境。
- `motion_suffix` 不要写 “clearly visible motion / lively movement” 这类催动作的词，写 “natural physics, steady camera”。
- 镜头长度：Wan 最多出 5 秒左右，render 慢放下限是 0.8 倍（以前是 0.55，那次 22/59 条慢于 0.8 倍，人笑、走路像梦游）。帧数按镜头实际长度生成（4n+1）。

## 审片清单（L2 每条片段都过一遍）
看 `clips/raw/shot_XX_review.jpg`（12 帧，4×3）：
1. 有没有东西凭空出现、消失、变形（数一遍物件）
2. 人数前后一致，同一个人的脸前后一致
3. 物理和因果：水往下流、门怎么开、手和物体怎么接触
4. 肢体、手指、脸有没有走样
5. 动作是不是分镜表写的那一个，而不是 Wan 自己加的
6. 硬规则（不露脸、服装、食物……）
7. 和前后镜头接不接得上（时间、光线、位置）

任何一项拿不准就 reject，或用 `--keep N` 截短，note 里写清是哪一项（例：“1：第 70 帧冒出肥皂瓶”）。**不要为了凑“都动起来”判 ok**：那次审片只卡了硬规则，成片很多画面不合逻辑。D6 用户的意见优先于你的审片。

## 模型选择（`pipeline.choose_model`，自动）
从上往下，取第一条命中的：

| 条件 | 模型 |
|---|---|
| 镜头写了 `"wan_model"` | 按写的 |
| 命令加了 `--model 5b\|a14b` | 按指定 |
| 命令加了 `--fast` | 5B 快速档（960×544、81 帧、16 步） |
| manifest 顶层写了 `"wan_model"` | 按写的 |
| 这个镜头之前用 5B 失败过（太静止，或审片 reject；卡死超时不算） | A14B |
| 有人物、手、人群，或动作里有表演动词 | A14B |
| 物体特写（`object`） | A14B |
| 其余：纯环境 | 5B 默认档（1280×704、121 帧、24 fps） |

对比测试（4 个镜头，每种 1 个种子，只当方向参考）：

| 方案 | 每条耗时（RTX 5060 Laptop 8 GB） | 结果 |
|---|---|---|
| 5B 20 步 | 13.8 分钟 | 人中途换脸、乱加动作、东西消失 |
| 5B + FastWan / Turbo LoRA 4 步 | 3.6 分钟 | 只是更快，同样的问题，所以没接进流水线 |
| A14B Q4 GGUF + lightx2v 4 步，848×480 @16 fps | 约 5 分钟 | 人物稳定，照提示做，突变最小 |
| SeedVR2 3B fp8 把 480p 放大到 1080p | 81 帧约 8 分钟 | 比 lanczos 明显清楚，批与批之间不闪 |
| 5B 20 步，提示词只写一个动作 | 13.9 分钟 | 也变合理了 |

最后一行说明：**动作写法比换模型更重要**，A14B 在此基础上更稳。

## 成功先验（`priors.json`，只统计 5B，随 review 更新）
| class | 先验 | 说明 |
|---|---|---|
| atmosphere | 0.90 | 没有人的远景也可能冒出路人，负面词加“人物，行人” |
| object / hands | 0.85 / 0.80 | 后半段可能变形，靠自动截帧 |
| human_static | 0.50 | 动作只写呼吸、烛光；审片偏松时这个数会被高估 |
| human_motion / crowd | 0.35 / 0.30 | 远景队伍可以，近景走路风险高 |
